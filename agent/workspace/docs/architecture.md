# Архитектура backend

## Слои приложения
Backend WordMaster построен по классической слоистой архитектуре Spring: Controller → Service → Repository → Database. Controller принимает HTTP-запрос, проверяет входные данные аннотациями валидации и вызывает сервис; он не содержит бизнес-логики и не обращается к базе напрямую. Service содержит бизнес-логику: создание и копирование колод, подсчёт статистики, выдачу карточек для тренировки, проверку прав владельца. Repository — интерфейсы Spring Data JPA, через которые сервисы читают и пишут сущности; SQL вручную пишется только для сложной статистики. Database — PostgreSQL. Каждый слой знает только о соседнем снизу, поэтому сервис можно протестировать без HTTP, подменив репозиторий моком в Mockito. Транзакции открываются на уровне сервиса аннотацией @Transactional: например, копирование колоды создаёт новую колоду и все её карточки в одной транзакции, и при ошибке на середине в базе не останется «половины» копии. Исключения сервисов переводятся в HTTP-коды в одном месте — глобальном обработчике @RestControllerAdvice.

## DTO и маппинг
Сущности JPA (Entity) никогда не уходят наружу через API. Для каждого запроса и ответа есть свой DTO, а преобразование Entity ↔ DTO выполняет отдельный Mapper. Так в ответ не попадёт passwordHash, а изменение схемы БД не ломает контракт API.

## Технологии
Java 25, Spring Boot 3 (Spring Web, Spring Data JPA, Spring Security), PostgreSQL, Lombok для сокращения шаблонного кода и Maven для сборки. Фронтенд — многостраничный HTML, CSS и Vanilla JavaScript: каждая страница отвечает за одну функцию и обращается к API через fetch, без фреймворков и SPA-роутинга.

## Структура пакетов
Код лежит в пакете com.wordmaster и разбит по ролям: controller, service, repository, entity, dto, mapper, security и config. Настройки подключения к базе — в application.yml, статические страницы фронтенда — в resources/static.

## Запуск и тесты
PostgreSQL поднимается через docker-compose up -d db, приложение — командой ./mvnw spring-boot:run, после чего оно доступно на http://localhost:8080. Unit-тесты пишутся на JUnit 5 и Mockito, интеграционные тесты репозиториев — на Testcontainers с настоящим PostgreSQL в контейнере.
